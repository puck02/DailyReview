# DailyReview 界面与性能优化设计

## 目标

在不更换 React、Vite、Cloudflare Workers 和现有数据模型的前提下，解决移动作文裁切、聊天流式渲染抖动、移动导航过密和 Worker 热路径串行开销，并建立克制、一致的学习工作台视觉语言。

## 设计原则

- 优先保证学习任务可完成，再处理视觉修饰。
- 保留现有功能和页面入口，不新增业务能力。
- 用户数据继续使用 `no-store`，不引入 CDN 公共缓存。
- 核心消息必须在流结束前可靠落库；Token 统计等旁路数据允许后台写入。
- 只在真实热点上增加抽象，避免为了拆文件而拆文件。

## 信息架构与视觉方向

产品采用“克制的学习工作台”风格。背景使用轻微染色的中性色，正文使用墨色，淡紫只表示当前选中和学习状态，成功与警告分别使用低饱和绿色和琥珀色。圆角收敛为 6、8、12px 三档，减少大面积阴影、模糊和浮动卡片。

桌面端保留窄图标导航。移动端底栏只展示问答、翻译、作文、报告四个高频入口，账户按钮承载 AI 设置、普通设置和退出。设置页使用分组行和分隔线，报告页保持纸张阅读感，聊天页保持平静的工具界面。

作文桌面端继续使用题图、正文、补全三栏。移动端改为题图、正文、补全三个 Tab，默认进入正文；正文顶部显示题图状态摘要。作文正文使用正式 serif 字体链，不再使用 Comic Sans。

## 交互与可访问性

聊天仅在用户位于底部附近时自动跟随流式回复。用户向上阅读后暂停跟随，并提供回到底部按钮。

所有移动触控目标至少 44x44px。词云在桌面端降低节点数量，在移动端停止跑马动画并允许横向浏览。`prefers-reduced-motion` 下关闭词云和非必要动画。

建立统一 Dialog 组件，负责初始焦点、Tab 焦点循环、Escape 关闭、遮罩关闭和关闭后焦点恢复。词云详情、题图预览、截图编辑器和手写板逐步使用同一基础行为。

## 前端性能设计

聊天消息拆成可记忆的 `MessageItem`，流式更新只重渲染当前助手消息。移除 Markdown 内容 `key`，插件加载使用模块级共享 Promise。流式阶段按固定间隔合并 UI 更新，最终回复再执行完整 Markdown、KaTeX 和代码高亮。

作文幽灵文本的滚动位置通过 RAF 和 DOM transform 同步，不进入 React state。自动保存使用单写队列和版本号，旧请求不能覆盖新草稿；离开会话前刷新最后一次待保存内容。

已访问页面可继续保留必要状态，但隐藏页面必须暂停动画、轮询和建议请求。

## Worker 性能设计

所有表、列和索引由 `schema.sql` 或集中式迁移模块创建，业务路由不直接包含 DDL；迁移结果按 D1 binding 在 Worker isolate 内复用。AI 配置允许 Worker isolate 内短期缓存，管理员更新后立即失效。

聊天附件使用单次所有权查询和批量关联。消息、会话时间及图片上下文等核心写入合并执行；Token 使用记录通过 `ExecutionContext.waitUntil` 写入。聊天历史使用最近消息窗口和滚动摘要，避免无限增长的模型上下文。

作文会话列表一次查询返回题图附件，避免逐会话查询。翻译的自动词条提取在主翻译响应后通过 `waitUntil` 执行，并使用批量去重和插入。非流式 AI 请求必须转发客户端中止信号，并限制整个候选模型链的总超时。

## 错误处理

自动保存失败保留本地草稿并展示内联错误，不回滚用户当前输入。后台 Token 统计或自动词条失败只记录日志，不覆盖主任务成功结果。流式聊天中断继续保持“未收到 DONE 即失败”的现有语义。

## 测试与验收

- 前端单元测试覆盖自动滚动判断、流式更新合并、保存版本和移动导航结构。
- Worker 测试覆盖零 DDL 健康检查、附件批量校验、历史窗口、翻译后台入队和请求中止传播。
- 在 360、390、430px 宽度及 1440px 桌面视口做浏览器截图和布局断言。
- 移动端无页面级横向滚动或作文内容裁切，主要触控目标至少 44x44px。
- 100 条历史消息流式输出时，用户向上阅读不会被拉回底部。
- `/api/health` 不访问 D1；聊天调用上游前的应用侧 p95 目标低于 300ms。
- 真实生产环境后续以 p75 LCP <2.5s、INP <200ms、CLS <0.1 为目标。

## 保留项

继续保留 Markdown 按需拆包、报告内容内存缓存、图片上传前压缩、现有 AbortController、D1 索引、静态资源 immutable 缓存、暗色模式和截图、手写板、图片粘贴能力。
